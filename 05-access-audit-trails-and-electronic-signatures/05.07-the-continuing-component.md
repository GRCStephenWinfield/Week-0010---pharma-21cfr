## 1. What this chapter settles

`21 CFR 11.200(a)(1)` requires a non-biometric electronic signature to employ at least two distinct
identification components. `21 CFR 11.200(a)(1)(i)` permits subsequent signings within a single continuous
session to use one component, and says which one it may be. **This chapter reports which of the nineteen
systems that execute electronic signatures re-prompt for the right component and which re-prompt for the
wrong one.**

**Seven of the nineteen re-prompt for the user identification code rather than the password.**

The chapter also disposes of the two things `21 CFR 11.200` is most often said to require and does not.
**It is not a multi-factor authentication requirement**, and it does not make biometrics obligatory.

## 2. `21 CFR 11.200(a)(1)`, and the two components

**Verbatim:** electronic signatures that are not based upon biometrics shall

> *"Employ at least two distinct identification components such as an identification code and password."*

**Read the sentence for what it actually asks.** It asks for two components, it asks for them to be
distinct, and it gives an identification code and a password as its own example of a pair that satisfies
it. **An identification code and a password satisfy `21 CFR 11.200(a)(1)`.** Nothing further is required by
the text.

**This is not multi-factor authentication and this repository never calls it that.** Modern multi-factor
authentication is a different standard from a different tradition, built on the idea of factors of
different kinds — something known, something held, something inherent — and it happens to overlap with the
regulation's requirement without being the same thing. **Two components of the same kind, both known,
satisfy `21 CFR 11.200(a)(1)`; a firm that deploys multi-factor authentication has done something Part 11
does not require of it.** Where Helix deploys it, that is Helix's decision and this repository says so.

**Biometrics are a separate permitted route and are never required.** `21 CFR 11.200(b)` makes a
biometric-based signature an alternative, and it is an alternative and not an obligation. No system in this
estate uses one, and that is not a gap.

**`21 CFR 11.300` is a different section and is not this chapter's.** It governs controls over
identification codes and passwords — uniqueness of the combination, periodic checking, recall or revision
of issuances, loss management, transaction safeguards and device testing. `21 CFR 11.300(b)` requires
issuances to be *"periodically checked, recalled, or revised (e.g., to cover such events as password
aging)"* and **specifies no interval; there is no Part 11 password interval, and any interval Helix sets is
a company procedural decision.** `05.04-access.md` owns that ground.

## 3. `21 CFR 11.200(a)(1)(i)`, and what it permits

The subparagraph deals with a series of signings performed one after another without the signer leaving the
system.

**Verbatim, in two fragments as the sources carry them.** The series is one performed during

> *"a single, continuous period of controlled system access"*

and within such a period the first signing uses all of the components, while

> *"subsequent signings shall be executed using at least one electronic signature component that is only
> executable by, and designed to be used only by, the individual."*

**Two things are permitted and one thing is required.** What is permitted is the relaxation: after the
first signing, one component instead of two. What is required is the qualification on which component that
may be — **only executable by, and designed to be used only by, the individual.**

**And `21 CFR 11.200(a)(1)(ii)` closes the other half.** Where the signings are not performed during a
single continuous period of controlled system access, *"each signing shall be executed using all of the
electronic signature components."* There is no third case. **A session is continuous or it is not, and if
it is not, the relaxation is not available at all.**

## 4. The continuing component is the password

**A user identification code is known to others.**

That is the whole of the argument and it is a factual claim about the estate rather than an interpretive
one. **A user identification code appears in audit trails**, which is what makes an audit trail useful. **It
appears in reports** — every result listing, every batch record extract, every access review names the
individual by the identifier the system holds. **It appears on screens**, at the top of the session and
next to every entry. It is printed on distribution lists and typed into service requests. **It is the thing
the system uses to say who did something, and a thing designed to be shown cannot simultaneously be a thing
only executable by one person.**

**A password is the other half of the pair and it is the half nobody else has.** Whatever else is true of a
password regime, its whole design intent is that the value is known to one individual, and that is the
property `21 CFR 11.200(a)(1)(i)` asks for in the words *only executable by, and designed to be used only
by, the individual.*

**So the conclusion, stated as what it is.** On this estate the user identification code appears in audit
trails, in reports and on screens, so it is not a component **"only executable by, and designed to be used
only by, the individual"**; the password is. **The regulation names no component, and this is Helix's
determination on the facts of its own estate rather than a reading FDA has published.** No guidance and no
preamble resolves whether a user identification code could qualify on a different estate, and this chapter
does not decide that question.

**On the facts recorded here, a system that re-prompts for the user identification code within a session
has not met the subparagraph; one that re-prompts for the password has.**

`ADR-0033`, `DEC-514`, taken by Amara Sissoko on 2027-01-20: **the continuing component under
`21 CFR 11.200(a)(1)(i)` is the password, and each of the nineteen is tested as such.** The decision records
what was refused and why. What was refused was treating either component as acceptable on the ground that
the text says *at least one* and does not name which; **the reason it was refused is that the text does not
stop at *at least one* — the qualifying clause is the rest of the same sentence, and a reading that
satisfies the first half by ignoring the second is not a reading of the sentence.**

**What was equally refused was the opposite error**, which is to require both components on every signing
and treat `21 CFR 11.200(a)(1)(i)` as a trap. The relaxation is in the regulation and a firm is entitled to
use it. **A system that re-prompts for the password alone within a continuous session is compliant with the
subparagraph and is not doing anything second-best.**

## 5. The seven

**Seven of the nineteen re-prompt for the user identification code rather than the password on subsequent
signings within a single continuous period of controlled system access.**

| Cut | Systems |
|---|---|
| **Re-prompt for the user identification code** | **7** — `SYS-019`, `SYS-023`, `SYS-024`, `SYS-027`, `SYS-028`, `SYS-037`, `SYS-042` |
| Re-prompt for the password, or require both components on every signing | **12** — `SYS-001`, `SYS-025`, `SYS-026`, `SYS-039`, `SYS-040`, `SYS-041`, `SYS-043`, `SYS-044`, `SYS-047`, `SYS-048`, `SYS-049`, `SYS-050` |
| **Check** | **7 + 12 = 19** |

**The seven are not a further population. Every one of the seven is also among the twelve** at
`05.06-signatures-and-the-human-readable-form.md §6`, so twelve of the nineteen carry at least one signature
finding, seven of those twelve carry both, and seven of the nineteen — `SYS-025`, `SYS-026`, `SYS-041`,
`SYS-043`, `SYS-047`, `SYS-048` and `SYS-049` — carry neither. **The two identities partition the nineteen
twice on different properties, and the equality of the numerals is a coincidence and not a relation.**

**The seven were tested in the same way and the test is worth stating**, because the behaviour is only
visible in a session and not in a configuration screen. For each of the nineteen, a first signing was
executed with both components and a second signing was executed in the same uninterrupted session, and
**what the system asked for the second time was recorded.** The records are `EV-519`, one per system, and
the enumeration of which of the nineteen offer a continuous-session relaxation at all is `EV-518`.

**On the seven, the second prompt asks for the identifier the audit trail is about to print.** That is the
sentence to hold on to. The system asks the signer to re-enter, as the thing only they can supply, the
string it will then display next to their entry.

**Five of the seven are laboratory systems and two are not**, and no inference is drawn from that here. The
distribution is a fact about which products were bought for which function, and no document in this
repository assesses any individual's work or any function's.

**The `OBS-2` link is recorded and no conclusion is drawn from it.** `SYS-023` and `SYS-024` are among the
seven. **The chromatography-specific work is Phase 06's**, `MS-10`, and nothing in this chapter bears on it.

## 6. What the seven are, and what they are not

**They are a failure to meet `21 CFR 11.200(a)(1)(i)` and they are nothing more than that.**

- **The first signing in every session on all nineteen uses both components.** `21 CFR 11.200(a)(1)` is met
  on all nineteen; it is the relaxation at `(a)(1)(i)` that is taken incorrectly on seven.
- **This is not a statement that any signature is invalid, forged or repudiable.** It is a statement about
  which component a system asks for. **No document in this repository reaches a legal conclusion of any
  kind.**
- **It is not a control position under `21 CFR 11.10`.** `21 CFR 11.200` is in Subpart C.
  **No cell in `logs/control-position-register.md` moves because of anything in this chapter**, and the
  seven do not appear in `logs/control-gap-register.md`, whose unit is a paragraph of `21 CFR 11.10`.
- **It is not a multi-factor authentication finding**, because there is no multi-factor authentication
  requirement in Part 11 to fail.
- **It is not a password policy finding.** Nothing here concerns password length, complexity, history or
  expiry, and **no interval is specified anywhere in Part 11** — `21 CFR 11.300(b)`, `05.04-access.md`.
- **It is not a validation outcome, a deviation or a CAPA.** **No validation package has been executed, no
  protocol has been run and no test result under Phase 04's framework exists**, and **a control gap is not
  a deviation** — `05.12-what-this-does-not-establish.md`.
- **It is not a criticism of a vendor.** A product that offers the relaxation and prompts for the wrong
  component offers a configurable behaviour, and **compliance is a property of Helix's validated system in
  its intended use.** There is no Part 11 certification and no FDA-approved or FDA-validated software.

## 7. Why this one is easy to get wrong

**Because the subparagraph reads like a convenience and is drafted like a control.**

The relaxation exists for a real reason: an analyst signing forty results in a sitting, an operator signing
each step of a packaging run. Requiring both components forty times is friction with no return, and the
regulation says so by permitting one. **What a reader takes from that permission is that the second prompt
is a formality**, and a formality is naturally implemented with the field that is easiest to type and
hardest to mistype — which is the user identification code, because the system already knows it.

**The qualifying clause then reads as descriptive rather than restrictive.** *At least one electronic
signature component that is only executable by, and designed to be used only by, the individual* is a long
clause in a subparagraph whose headline is a relaxation, and a reader skimming for the permission stops at
*at least one*.

**And nothing in the estate required anybody to look.** No procedure requires a system's continuous-session
behaviour to be tested against `21 CFR 11.200(a)(1)(i)`, and a behaviour nobody is required to test is a
behaviour nobody tests. **That is the same class of absence as the one at `05.06-signatures-and-the-human-readable-form.md §7`,
and the same class Phase 04 published as its twelve** —
`../04-the-validation-framework-and-policy-architecture/04.08-where-the-obligations-land.md §5`, `IS-24`.
The argument is not restated here.

## 8. What would close it

**Stated as the condition, not as a plan.** No date, no cost, no sequence.

| For | The condition |
|---|---|
| The seven | **The subsequent-signing prompt set to the password**, or the continuous-session relaxation withdrawn so that every signing uses all components under `21 CFR 11.200(a)(1)(ii)` — evidenced by a recorded session test on each system |
| All nineteen | **A procedure requiring the continuous-session behaviour to be tested against `21 CFR 11.200(a)(1)(i)`**, so that the test that found this is required rather than remembered |
| The estate | **The enumeration at `EV-518` kept current**, because a product update can introduce a relaxation where none was offered before |

**Withdrawing the relaxation is a lawful answer and it is the more expensive one**, because it puts the
friction back. It is named as an option rather than recommended, because this phase recommends nothing:
**no remediation plan, no remediation cost, no sequence and no priority is stated anywhere in Phase 05.**

**`IS-31` carries the seven**, owned by Amara Sissoko, raised 2027-01-20, open. Nothing is closed by this
chapter.
